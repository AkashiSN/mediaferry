## はじめの一周

初回はこの順に進みます。

1. **設定 › 送り先**で Immich を登録する
2. カードを挿す。**ホーム**に出るので「いま取り込む」
3. そのカードを**信頼する**（初めて見るカードで毎回止まらないようにする）
4. ホームの**やること**に出た「送る」を押す

**2 回目からは「カードを挿す →「いま取り込む」→ 送る」の 3 手**です。

> **いまは、挿しただけでは取り込まれません。** 信頼したカードでも、新しく撮った
> ファイルを見つけるには**ホームの「いま取り込む」を押す必要があります**
> （中身を数える段が、挿したときには走らないためです）。詳しくは
> [取り込みが自動で始まらない](#取り込みが自動で始まらない)。

## 画面の地図

**ナビゲーションは「ホーム / 写真 / 設定」の 3 つだけ**です。それ以外の画面は、
この 3 つの下にあります。

| 場所 | 何をするところか |
| --- | --- |
| **ホーム** | いま挿さっているカード、**やること**、進行中の作業、送り先ごとの状況、さっき取り込んだもの |
| **写真** | 取り込んだものを日付ごとのグリッドで見る。絞り込んで選び、まとめて送る |
| **設定** | 自動取り込みの切り替え、送り先、カメラの種類、そして 3 つの節 ——「**ふだんは使わない操作**」（つなぐ・日時の確認・接続中のカード）、「**記録**」（作業の履歴・つないだ後の後片付け・使っていないファイル）、「**詳しい設定**」（環境の設定とリセット） |

ホームの下には、作業のページが 5 つあります。**ナビゲーションの項目は増えません。**

| ページ | どこから開くか |
| --- | --- |
| **カードの中身** | ホームのカードの帯の「中身を見る」（設定 › ふだんは使わない操作からも） |
| **つなぐ** | やることの「つなぐ」 |
| **確認** | やることの「確認する」 |
| **送る** | やることの「送る」、または写真で選んでから「送る」 |

## 取り込む

カードを挿すと**ホーム**の上に帯で現れます。判別した機種と、**そう判断した理由**は
帯の「中身を見る」（**カードの中身**の画面）で読めます。

| 出るもの | 意味 |
| --- | --- |
| `DJI Osmo Pocket` / `Canon EOS` / `汎用 DCIM` | 機種を判別できました |
| **対象外** | どのカメラの種類の条件も満たしません。**理由も出ます** |
| **対象だが中身が無い** | 構造は合っているが、対象のファイルがまだ 1 つもありません |

ホームの帯の**「いま取り込む」**は、中身を数えてからコピーします。**カードの中身**の
画面では、**「◯◯ をスキャン」**（数えるだけ）と**「◯◯ を取り込む」**（コピー）を
別々に押せます。スキャンは何度でも安全です（読むだけです）。

コピーはカードの並びをそのまま保ちます。

```
カード:  DCIM/100CANON/IMG_0001.JPG
NAS:     library/canon-eos/DCIM/100CANON/IMG_0001.JPG
```

**同じファイルを二度取り込むことはありません。** サイズと更新時刻に加えて、
ファイルの中身から作った指紋で照合します。カードを初期化して連番が一周しても、
別のファイルとして扱われます。

### 信頼登録（2 回目から自動にする）

**「このカードを信頼する」**（カードの中身の画面では**「◯◯ を信頼する」**）を押すと、
そのカードは**初めて見るカードの扱いから外れます**。確認のダイアログには、いま何が
起きるかがそのまま書かれています。

**ただし、いまは挿しただけでは取り込まれません。** 確認のダイアログは「挿すだけで
NAS へコピーされます」と書きますが、**中身を数える段が挿したときに走らない**ので、
実際には 1 件も取り込まれません（下の「取り込みが自動で始まらない」）。取り込むには
**ホームの「いま取り込む」**を押してください。

**初めて見るカードは必ず止まります。** `DCIM` を持つ USB ドライブは何でも
`generic-dcim` に当てはまるので、他人のスマートフォンやバックアップディスクを
挿しただけで中身が NAS にコピーされる、という事故を防ぐためです。

**信頼しても自動にならない場合があります。** カードを同定できないとき
（ファイルシステムに UUID が無い媒体など）は、承認済みでも毎回確認を求めます。
画面にもその旨が出ます。

**アップロードは信頼登録に関係なく、常に手動です。**

## 送り先を登録する

**設定 › 送り先**で、名前・接続先 URL・API キーを入れて
**「接続を検証して追加する」**を押します。

**検証に失敗した設定は保存されません。** URL の打ち間違いや、権限の足りない
API キーは、この時点で分かります。

- **複数の Immich を登録できます。** 同じ写真を 2 か所へ独立に送れます
- **同じライブラリを指す送り先が 2 つあると、画面が知らせます**（禁止はしません。
  内部用と VPN 用で URL を分ける、といった使い方があるためです）
- API キーは暗号化して保存されます。画面にも API 応答にも出てきません

### 向き先を変えたとき

URL や API キーを編集すると、mediaferry は**同じ Immich を指したままか**を
確かめます。

| 変更 | 送信履歴 |
| --- | --- |
| API キーの入れ替え、内部 URL の変更（同じアカウント） | **引き継ぎます** |
| 別のアカウント・別のサーバへの変更 | 引き継ぎません（新しい送り先として扱います） |
| ホスト名が変わり、アカウントは同じ | **どちらか尋ねます**（復元したサーバかもしれないため） |

## 送る

**送る**の画面は**「どこへ送りますか」→「何を送りますか」→ 確認**の 3 段です。
宛先を選び、対象を選び、**「内容を確かめる」**を押して、確認して**「実行する」**。

- **既定は「まだ送っていないもの、すべて」**です。前回の続きを全部送る、が 1 手で済みます
- ほかに「いちばん新しい撮影日のぶんだけ」と「写真を自分で選ぶ」があります。
  **写真**の画面で選んでから「送る」を押した場合は、その選択が既定になります
- 送るを押すと**ホーム**へ戻り、**押した操作**にその送信が出ます
  （画面を開いたままにする必要はありません）。断られた写真や、始められなかった
  送り先があれば、そこに書いてあります。終わった作業は
  **設定 › 記録 › 作業の履歴**で見られます
- **既に Immich にある写真は上げ直しません。** チェックサムで照合します。
  Immich のゴミ箱にあるものも「ある」と扱い、**勝手に上げ直しません**
  （利用者が消したものを黙って復活させないためです）

### 送れないもの・出てこないもの

| 状況 | 理由 |
| --- | --- |
| つないだグループの元パーツ | つないだ結果を送るので、既定では出しません |
| 検証に落ちたつないだ結果 | 中身を確認して**「中身を見て、これを使う」**を押すと選べるようになります |
| ファイルが見つからない | NAS 上から消えているものは送れません |

## 確認（日時の書き戻し）

**他人が上げた写真の日時を、こちらが勝手に書き換えないための段**です。

mediaferry は自分が上げた写真の撮影日時を直せますが、**チェックサムが一致しただけ
の写真**（誰かが先に上げたもの）は「自分が上げた」と証明できません。この場合、
ホームの**やること**に「確認」が出て、**確認**の画面に「いまの値」と「直したい値」を
並べて出します。

- **承認する** — 書き戻して完了にします
- **却下する** — **リモートには一切触らず**完了にします（既に正しい場合）

カメラの種類が日時の補正をしない設定なら、やることにも画面にも何も出ません。

## 分割された動画をつなぐ

DJI は 4GB ごとに動画を分割します。**つなぐ**の画面で
**「分かれた動画を探す」**を押すと、連続した並びを探します。

1. 候補が出たら、中身（パート数・合計時間・つなぎ目の空白）を確認して**「つなぐ」**を押します
2. つないだ結果は**自動で検証**されます（時間・ストリーム・継ぎ目）
3. 合格すれば、以後はその 1 本が送信の候補になります

**つなぐ画面に出るのは、まだつないでいないものだけです。** つないだ動画は
**写真 › つないだ動画**に並びます。

**検出が拾えなかった並び**は、**「手でグループを作る」**から 2 件以上選んで
組めます。別の撮影だった場合は**「これは別々」**で外します（外した組み合わせは
**設定 › 記録 › つないだ後の後片付け**に残ります）。

### つないだあとの操作

つないだ動画を**写真タブで開く**と、検証の結果と次の操作が出ます。

- **「中身を見て、これを使う」** —— 検証に落ちた結果を、中身を見たうえで採用します
  （落ちても元のパーツは消えません。採用しないと送信の候補に出ません）
- **「同じ構成でやり直す」** —— 同じパートでつなぎ直します
- **「構成を変える」** —— 残すパートを選び直します
- **「これは別々」** —— 別々の動画として扱います

> Canon の分割は既定で無効です。連番から分割かどうかを判別する根拠が実データで
> 取れていないためで、誤って別々の撮影をつなぐと元ファイルが取り残されます。

## RAW+JPEG を束ねる

RAW+JPEG を同時記録すると、Immich には 2 枚として並びます。mediaferry は
**同じシャッターで出た組を 1 つのスタックにまとめます**（既定で JPEG が代表）。

組と認めるのは、次を**すべて**満たすときだけです。

- 同じカードの、同じフォルダの、**同じ名前**（`IMG_1234.JPG` と `IMG_1234.CR2`）
- **撮影時刻が一致**する
- 時刻の**根拠が同じ**（EXIF どうし、または mtime どうし）
- **両方とも mediaferry が上げた**もの

**束ねられなかった組は、理由が設定 › 送り先の画面に出ます。** 「相方が見つからない」
「撮影時刻が一致しない」「相手側に別のスタックがある」など、そのままの言葉で出ます。

**利用者が手で作ったスタックには触りません。** ただし Immich の API には
「条件付きで作る」手段が無いため、**読み取ってから作るまでの一瞬に別の操作が
入った場合だけは、こちらの操作が相手のスタックを取り込むことがあります。**

## カメラの種類（機種プロファイル）

**設定 › カメラの種類**で確認・編集できます。最初から入っている 3 つは直接編集
できませんが、**「複製して変える」**を押せば自分用に変えられます。

編集は YAML で行い、次を決められます。

| 節 | 決めること |
| --- | --- |
| `hints` | 候補の順位付けに使う手がかり（USB の ID、ボリュームラベル） |
| `require` | **そのカードだと確定する条件**（フォルダ、ファイル名、最低件数） |
| `scan` | 取り込む対象（フォルダ、拡張子） |
| `timestamp` | 撮影日時の取り方（ファイル名 / EXIF / 更新時刻）と、時差の扱い |
| `merge` | 分割動画の結合（有効・無効、許容差、連番の読み方、出力名） |
| `stack` | RAW+JPEG の組（有効・無効、拡張子の優先順、時刻の許容差） |
| `immich` | 付けるタグ、既存写真にもタグを付けるか、日時を書き戻すか |

**「◯◯ で試す」**を押すと、いま挿さっているカードに対してその規則がどう当たるかを
確かめられます。**保存する前に試せます。**

**編集しても過去のデータの解釈は変わりません。** 保存すると新しい版が作られ、
既に取り込んだものは取り込んだときの版のままです。

## 撮影日時をあとから直す

タイムゾーンの設定を後から入れた場合など、**既に取り込んだものの撮影日時を計算し
直せます**。設定 › カメラの種類の**「撮影日時を再計算する」**です
（タイムゾーンそのものは**設定 › 詳しい設定**で変えます）。

- **ファイルは動きません。** 記録された日時だけを計算し直します
- 送信済みのものは、値が変わったときだけ「要確認」に戻り、次の送信で Immich 側も
  直ります
- スタックの見送りも、時刻が変われば**もう一度評価し直されます**

## 画面に出る時刻の読み方

**時刻には必ず「（JST）」のような印が付きます。** どの時計の数字かを、読む人が
推測しなくて済むようにするためです。

| 出るもの | 何時のもの |
| --- | --- |
| **作業の履歴の「終わった日時」**、送り先の「最後に確かめた」、確認画面の「観測した時刻」 | **設定 › 詳しい設定のタイムゾーンに直して**出します |
| **撮影日時** | **撮った土地の時刻のまま**出します。印はその値のゾーンから作ります |

**撮影日時を直さないのは、「現地で何時だったか」を残すためです。** 海外で撮った
写真は現地の時刻のまま（例: `14:20（GMT+2）`）出ます。日本で撮ったものは
`12:33（JST）` になるので、ふだんは印が付いただけに見えます。

**カメラの種類がタイムゾーンを決めていない場合**は、設定したタイムゾーンのものと
みなして印を付けます。

**日付だけの見出し**（写真の日ごとの区切り、送る画面の期間）には印を付けません。

## やり直す（リセット）

**設定 › 詳しい設定 › リセット**から、段階的に消せます。

**消えるのは mediaferry が持っているものだけです。Immich にある写真は消えません。**

| 段 | 何が消えるか | 元に戻せるか |
| --- | --- | --- |
| 作業の記録 | 作業の履歴と、別々にした組み合わせの記録 | もう一度探せば戻ります |
| 送信の記録 | どれをどこへ送ったかの記録 | **戻せません**（下を読んでください） |
| 取り込んだファイル | NAS に取り込んだ写真と動画、つないだ動画 | カードに元があれば取り込み直せます（下を読んでください） |
| すべて | 上のすべてと、カードの記録（どのカードを信頼したか） | **戻せません** |

**送り先とカメラの種類は、どの段でも残ります。** 接続のやり直しは要りません。

> **送信の記録を消すと、戻せない影響があります。** Immich の写真は残りますが、
> 次に送ったときに「自分が上げた」と証明できなくなります。そのため撮影日時の
> 自動補正は 1 件ずつの承認に変わり、RAW と JPEG を 1 枚に束ねるのも行われなく
> なります。**取り込んだファイル**と**すべて**の段も、送信の記録を含みます。

> **取り込んだファイルを消すと、挿さっているカードは数え直されます。** しばらく
> すると**ホーム**に「◯ 件を取り込む」が戻るので、そこから取り込み直せます。
> **取り込みは自動では始まりません** —— 消したばかりのものを黙って戻さないためで、
> 取り込むかどうかはボタンを押して選んでください。

走っている作業がある間はリセットできません。**設定 › 記録 › 作業の履歴**で
終わるのを待ってから、もう一度押してください。

**取り込みの途中だったものや、送信の途中だったものが残っているときも断られます。**
その場合はアプリを再起動すると片付くので、そのあとでもう一度押してください。

## 困ったとき

### カードが「対象外」と出る

**カードの中身**の画面に**判別できなかった理由**が出ます。多くは
`require.filename_pattern` に合うファイルが無い場合です。カメラの種類を複製して
`require` を緩め、**「◯◯ で試す」**で確かめてください。

### 取り込みが自動で始まらない

**いまは、信頼していても挿しただけでは取り込まれません。** 挿したときに走るのは
コピーの段だけで、**中身を数える段が走らない**ため、新しく撮ったファイルが 1 つも
見つかりません（コピーの記録は「成功・0 件」で残ります）。

**取り込むには、ホームの帯の「いま取り込む」を押してください。** このボタンは
数えてからコピーします。カードの中身の画面なら「◯◯ をスキャン」→「◯◯ を取り込む」
です。

そのうえで、次も確かめてください。

- 信頼が済んでいますか（ホームの帯と、カードの中身の画面で確認できます）
- 設定の**「信頼したカードを自動で取り込む」**が切ってありませんか（`AUTO_IMPORT`）
- **カードを同定できていない**可能性があります。画面にその旨が出ます

### 送信が始まらない・進まない

- 送り先が**休止中**または**退役済み**になっていませんか（設定 › 送り先）
- `MEDIAFERRY_SECRET_KEY` は設定されていますか（無いと送り先を開けません）
- **設定 › 記録 › 作業の履歴**に理由が出ます
- **相手が落ちていたなどで失敗したものは、設定 › 送り先の「送り直す」で送り直します。**
  失敗した記録は「まだ送っていない」に入らないので、ふつうに送るだけでは拾われません
  （送り先ごとに「送れなかったもの ○ 件」と出ます）

**大きな動画だけが失敗する場合**は、リバースプロキシの上限に当たっている可能性が
あります。[`tools/large_upload.py`](../tools/README.md#large_uploadpy--大きな動画が送れないとき)
でどこまで通るかを測れます（実測では CDN 経由が 622 MiB で 502、内部経路は
28.36 GiB が完走しました）。

### やることの「確認」が減らない

承認は**明示的な操作**です。日時を直す必要が無ければ**却下する**で構いません
（リモートには一切触らずに完了します）。

### Immich でゴミ箱に入れた写真が「送信済み」のまま

**そのとおりに表示しています。** Immich のゴミ箱にあるものは重複として扱われる
ため上げ直しません（利用者が消したものを、黙って戻さないためです）。

本当に送り直したい場合は、**Immich 側で完全に削除してから、設定 › 送り先の
「状態を再確認する」**を押してください。資産が消えていれば、その記録は
「リモートに存在しない」ものとして記録し直されます。

再確認は**写真のくわしく**（写真を押して開く画面）の送り先の行にある

**ゴミ箱にあることを送り先の一覧に出すところは、まだ実装していません**

### 起動しない

## 実機で確かめる

**この 16 項目は、実際のカードとハードウェアでしか確かめられません。**
初めて本番のカードを扱うときは、[`hardware-checklist.md`](hardware-checklist.md)
に沿って進めると、想定と違う点を早く見つけられます。

特に次の 2 つは、結果によって設定を変える必要があります。

- **11 番**（更新時刻の解釈）— 撮影日時の決め方の前提です
- **13〜16 番**（Canon の実カード）— RAW+JPEG の組・分割の判別・Immich が CR2 を
  受け取るか
