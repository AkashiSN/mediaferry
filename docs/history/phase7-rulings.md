# Phase 7 の裁定（番号の索引）

**コードとテストのコメントが「裁定 N」と書いているのは、この表の N です。**

Phase 7 は 13 のタスクを 1 つずつ実装 → レビュー → 修正で進めた。レビューで
「仕様とブリーフが衝突している」「指摘を容れるか退けるか」が出るたびに、
進行役が**番号を振って裁定**し、実装者へ渡した。コードのコメントはその番号を
根拠として引いている。

**この表が載せるのは、コード・ドキュメント・コミット本文が引いている番号だけ。**
**番号の全文（1〜58）は [`phase7-record.md`](phase7-record.md) の「裁定の全件」にある。**
元の作業ログはリポジトリの外（エージェントの作業ディレクトリ）にあって追跡されて
いなかったので、消える前にそちらへ移した。理由の一部は
`git log 5439d84..HEAD` のコミット本文にも残っている。

**呼び方は「裁定 N」に揃えた。** 同じものが `Ruling 12`（`work/Merge.tsx`）と
`裁定 12`（`work/Merge.test.tsx`）の 2 通りで呼ばれていて、grep で片方しか
見つからなかった。

**ここに無い番号がある。** 1〜7・9〜11・13〜15・17〜18・21〜29・32〜40・43〜48・
50〜52 は、実装の中に痕跡を残さずに終わったもの（テストの補助関数の署名合わせ、
生き残り変異の潰し方、タスク間の分担など）。**それらも含めた全文は
[`phase7-record.md`](phase7-record.md) にある。**

## この作り方から分かったこと

**番号は、それを引くコードより先に消える。** 進行役の作業ログはリポジトリの外に
あり、コードのコメントだけが番号を持ち越した。**外にある文書を根拠として引く
なら、引いた側の中に根拠の写しを残す。**

**根拠の呼び方は 1 つに決める。** `Ruling 12` と `裁定 12` が同じものを指して
いたので、どちらか片方で grep した人は半分しか見つけられなかった。
