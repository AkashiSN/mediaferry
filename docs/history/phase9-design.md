# Phase 9 の設計 —— 写真タブで、1 件を知って、いらなければ消せるようにする

**決まったこと（2026-08-25）。** 実装計画は `phase9-plan.md`、決着した判断は
`../decisions.md`、現在の仕様は `../design.md` §13 が正本になる。

## なぜこれをやるのか

**2026-08-23 の実機検証で、利用者が画面を触って見つけた。** 自動テストは全部
緑だった。同じ日に見つかった 7 件のうち 3 件は Phase 8 で閉じ、**残る 1 件が
これ**。中身は 4 つの症状だが、**1 つの設計課題**として出た。

> 写真タブで 1 件を選んで、**それが何かを知り、いらなければ消せる**。

| 実機で見えたもの | いまの姿 |
| --- | --- |
| **(1) 結合物だと分からない** | `web/src/components/MediaTile.tsx` が出すのは動画の尺だけ。API は `role: derived` を返しているのに画面が使っていない。絞り込み 6 つにも「つないだ動画」が無い |
| **(2) 写真タブに削除の経路が無い** | `Photos.tsx` にも `work/Send.tsx` にも `DELETE` を呼ぶところが無い。派生物を消せるのは 設定 › 詳しい情報 › 使っていないファイル だけで、そこに出るのは**もう使われていない**出力。**いま現役の結合物は画面のどこからも消せない** |
| **(3) 1 件の中身を見る場所が無い** | 撮影日時・尺・大きさ・どのファイルから作られたか、を出す画面が無い |
| **(4)「つないだ動画の記録」が名前と中身で食い違う** | 引いているのは `/merge-groups?status=skipped` と `/media/stale-derived` だけで、**成功した結合を 1 件も出さない**。どちらも 0 件だと画面全体が空になる |

**バラバラに直すと、また片側だけになる。** 写真タブの B-2 で一度踏んでいる。
だからモックで動線を決めてから実装計画を書く（Phase 7・Phase 8 と同じ進め方）。

## 決めたこと

モックを 3 面比べて決めた
（`.superpowers/brainstorm/*/content/{select-vs-open,detail-placement,merge-record}.html`。
追跡していないので残っていないことがある）。

| 決めたこと | 採らなかった案 |
| --- | --- |
| **押す＝開く。選ぶのは隅の丸**（Google フォト式） | 「押す＝選ぶのまま、開くのは `i`」（意味を憶える必要がある）、「選ぶモードに入る」（送るのに 1 手増える） |
| **専用の「くわしく」画面**（住所を持つ） | 下から出るシート（住所が無いので、他の画面から 1 件へ飛べず、(4) の直しが別の作りになる） |
| **成功した結合は写真タブへ寄せ、設定側は改名する** | 記録の画面に節を足す／成功を主役にして残りを畳む（**どちらも同じ一覧を 2 か所に作る**） |

**寄せる形を選んだ理由は、一覧が 1 つで済むこと。** 写真タブに「つないだ」の印と
絞り込みが入る以上、成功した結合はそこで見えている。設定側にもう一度並べると、
片方だけ直る形（B-2 の教訓）に戻る。

## 1. 写真タブ —— 押したときに何が起きるか

**タイルを押すと、その 1 件が開く。** 複数選ぶときはタイル右上の丸を押す。

| 操作 | 結果 |
| --- | --- |
| タイルを押す | `/photos/:id`（くわしく）へ |
| 隅の丸を押す | 選ぶ／選ぶのをやめる（送るための選択。いまの `selected` の Map はそのまま） |
| 長押し | 使わない |

**これは既存の操作を反転させる。** いま `MediaTile` は「押す＝選ぶ」で、
`aria-pressed` を持つボタンそのものが選択の的になっている。**単体テストと E2E で
タイルを押して選ぶものは、すべて丸を押す形へ書き換わる**（`Photos.test.tsx`、
`work/Send.test.tsx`、`web/e2e/` の巡回）。

**タイルの中に押せる的が 2 つできる。** §13 の 44px を両方が満たす必要がある。
3 列・390px ではタイルは約 118px なので、丸の当たり判定を 44px 取っても本体側に
余地は残る —— **ただし実測で確かめる**（E2E の「押せる的の大きさ」の錠に、丸を
含める）。

**「つないだ」の印を出す。** API が既に返している `role` を `MediaTile` が読み、
`role === "derived"` のとき左下に「つないだ」を出す（尺の表示とは反対側に置く）。

**絞り込みに「つないだ動画」を足す。** `FILTERS` に 7 つ目として加え、
`role=derived` で引く。**宛先ごとの絞り込みではない**ので `DESTINATION_SCOPED`
には入れない。

## 2. くわしく（`/photos/:id`）

**1 件を描くのに必要なものを 1 本の応答で返す。** 画面が複数の API を継ぎ足すと、
片方だけ古い状態が出る。

| 出すもの | 出どころ |
| --- | --- |
| 絵・ファイル名・撮影日時・長さ・大きさ | `media_file`（いまの `_media`） |
| **つないだ動画かどうか** | `role` |
| **元になったファイル**（順番どおり） | `merge_member` を `position` 順。1 件ずつ**その `/photos/:id` へ飛べる** |
| **宛先ごとの状況** | `upload_record`。「Immich に入っています」「Immich のゴミ箱にあります」「Immich にはもうありません」「まだ送っていません」「送れませんでした」 |
| **消せるか、消せないなら理由** | 下の §3 の規則をサーバが判定して返す |
| 操作 | 「送る」（既存の送る動線へ）と「消す」 |

**消せるかどうかをサーバが返す理由は、押しても 409 で断られるボタンを並べない
ため**（`list_stale_derived` が削除の前提と条件を揃えているのと同じ考え方）。
**規則は 1 か所に置き、一覧・詳細・DELETE の 3 つが同じ定義を使う。**

## 3. 消せる／消せないの規則

**消せるのは `role = 'derived'` の 1 件で、どの宛先にも「Immich に生きている」
観測が無いときだけ。** カードから取り込んだ元ファイルは、これまでどおり消せない。

| 記録の状態 | 判定 |
| --- | --- |
| 有効な記録が 1 つも無い（一度も送っていない） | **消せる** |
| `failed` だけ | **消せる** |
| `complete` だが再確認で `remote_asset_id` が外れた（`remote_checked_at` はある） | **消せる** |
| `remote_is_trashed = 1`（Immich のゴミ箱） | **消せる** |
| `remote_asset_id` があり、ゴミ箱でもない | 消せない（Immich に実在する） |
| `complete` だが `remote_asset_id` も `remote_checked_at` も無い（`0007` で洗った記録） | 消せない（**在るかどうかを観測していない**） |
| 送信中・確認待ち（`pending`・`checking`・`uploading`・`asset_known`・`tagging`・`fixing_datetime`・`awaiting_datetime_approval`・`needs_recheck`） | 消せない（決着していない） |

**`invalidated_at` が立っている記録は数えない**（§10。既存の `_status_clause` と
同じ）。

**「無い」には観測を要求する。** `remote_asset_id` が無いだけでは消さず、
**`remote_checked_at` が入っていること**（＝一度は確かめた）を条件にする。
`0007` を適用した DB には「向き先の記録が無い `complete`」が残っており、これは
**Immich に在るのに識別子を捨てただけ**かもしれない。`POST /uploads/{id}/requeue`
が同じ 2 列で送り直せる行を選んでいるのと、条件をそろえる。同じ理由で、
**`remote_is_trashed` が NULL で `remote_asset_id` があるものは「在る」側に倒す**
—— 観測していないだけで、無いことの証明ではない。

**ゴミ箱を「無い」扱いにするのは利用者の判断。** Immich で捨てたのだから、
こちらでも消せる。「Immich で捨てる → こちらでも消す」という後片付けの動線が通る。

### 消したときに起きること

1. **`upload_record` の行を消してから `media_file` を消す。**
   `upload_record.media_file_id` は `ON DELETE RESTRICT`（`0004`）で、外部キーは
   有効（`db/connection.py:51`）。**記録を残したまま行を消すことはできない。**
   Immich にも NAS にも無いものの記録なので、指す先が無い記録を残さない
2. **持ち主のグループが現行なら、「別々のままにした」（`skipped`）にする。**
   `merge_group` を `merged` のまま `output_media_file_id` だけ外すと、
   `merge_member` が `active` に残って**再検出も組み直しも塞がり、二度と
   つなげなくなる**（`0017` に、それで実機が詰まった記録がある）。破棄の規則は
   既存の `MergeRepository.discard()` を再利用する —— 構成ファイルが送信中のときに
   断る `_assert_editable` も一緒に効く。**ただし `immediate()` は入れ子にできない**
   ので、`discard()` を「トランザクションを開く版」と「開いている前提の版」に割り、
   削除は後者を自分のトランザクションの中で呼ぶ（破棄と削除が同時に成立する）
3. **DB を先に消し、実体は後で消す**（`delete_stale_derived` と同じ順）。
   逆にすると、途中で落ちたときに「レコードはあるのに実体が無い」状態になる
4. **元になったファイルが「まだ送っていない」に戻る。** `skipped` にすると
   trigger が member を `active = 0` にし、`SENDABLE_CLAUSE` の
   「active な member を持たない original」に当てはまるようになる。**これは
   いま「つなぐ」画面の「別々にする」を押したときと同じ挙動**であって、この
   設計が新しく作る驚きではない。**確認ダイアログで先に言う**
5. **戻せない。** `merge_group_discard_is_final`（`0017`）が `skipped` からの
   復帰を禁じている。確認ダイアログでそう名乗る

**現行でないグループの出力**（いまの「使っていない出力」に出るもの）は、これまで
どおり行を消すだけでよい。グループは既に `skipped` か superseded なので 2 は要らない。

## 4. 「つないだ後の後片付け」への改名

**成功した結合は写真タブの「つないだ動画」で見る。** 設定 › 詳しい情報の
「つないだ動画の記録」は、実際の中身どおり **「つないだ後の後片付け」** に改める
（節は「別々のままにした組み合わせ」と「使っていない出力」の 2 つのまま）。

**探しに来た人のために、案内を 1 行置く** —— 「つないだ動画そのものは
写真 › つないだ動画 で見られます」。設定 › 詳しい情報 の入口（`Settings.tsx` の
`DETAILS`）の名前と説明も揃える。

**API は据え置き。** `/merge-groups?status=skipped` も `/media/stale-derived` も
変えない。§13 の語彙表に「つないだ後の後片付け」を足す。

## 5. API の変更

| 変更 | 中身 |
| --- | --- |
| `GET /media` に **`role`** を足す | `_filters` に `m.role = ?` を 1 つ。「つないだ動画」チップが `role=derived` で引く |
| `GET /media/{id}` を**厚くする** | §2 の表のものを 1 本で返す。**`/media/stale-derived` より後ろに置かない**（既存の並び順の注意はそのまま） |
| `DELETE /media/{id}` の**規則を差し替える** | 「現行でないグループの出力」→「Immich に生きていない derived」。断る理由は**画面にそのまま出せる日本語**で 409 に載せる（`GroupNotEditable` の既存の形） |

**索引は測ってから決める。** `role = 'derived'` で絞ると `0014`
（`media_file (profile_id, captured_at DESC, id DESC)`）の経路から外れる。結合物は
行数が少ないので、`LIMIT` を満たすまでに何行走査するかが読めない。**実データに
近い行数で測ってから**足すかどうかを決める（`decisions.md` の「送信の記録の一覧の
索引」と同じ判断の仕方）。足すなら `0022`（`0021` まで使用済み）。

**`MergeRepository.discard()` の docstring を直す。** 「公開済みの派生物は消さない」
と書いてあるが、この設計で消す経路ができる。**呼ぶ側が消す**ことを書く。

## 6. どう確かめるか

**実装より先に、失敗するテストを書き、失敗を確認してから最小実装する。**

| 層 | 見るもの |
| --- | --- |
| 単体（サーバ） | **§3 の表の各行を 1 本ずつ。** 特に「`complete` かつリモート在り＝断る」「ゴミ箱＝消せる」「リモート消滅＝消せる」「**観測していない `complete`＝断る**」「進行中＝断る」「`role = original`＝断る」 |
| 単体（サーバ） | **消したら `upload_record` の行も消えていること。** 記録を残す実装では外部キーで落ちるので、**落ちることを先に見る** |
| 単体（サーバ） | **現行グループの出力を消したら、グループが `skipped` になり、元のファイルが「まだ送っていない」に戻ること** |
| 単体（サーバ） | 「消せるか」の判定が、一覧・詳細・DELETE で**同じ定義から出ていること**（定数か関数を 1 つにして、両方が使う） |
| 単体（画面） | タイルの丸と本体が別の的であること。「つないだ」の印が `role` から出ること。くわしくが元のファイルを `position` 順に出すこと |
| E2E | 巡回に 1 本足す —— **タイルを押す → くわしくが開く → 消す → 一覧から消えている**。結合物が要るので「手でグループを作る」経路を使う（`min_part_size_gib` の都合で検出は候補を作れない、の持ち越し） |
| E2E | 押せる的の大きさの錠に、**選ぶ丸を含める** |
| 実機 | 実際に結合物を 1 件消して、元の 4 本が戻ることと、Immich に在るものが断られること |

**受け入れコマンドに `npm --prefix web run test:e2e` を必ず入れる。** Phase 8 では
入っていなかったので、8 タスクぶん 4 本が赤のまま誰も気づかなかった（持ち越し）。

**E2E の spec ファイルを増やさない。** E2E はサーバを回収しないので（持ち越し）、
spec を 1 本増やすと孤児が 1 つ増える。錠は**既存の巡回 spec に足す**。

**変異試験を省かない。** `PYTHONDONTWRITEBYTECODE=1` を付け、実装の判断を 1 つ
ずつ壊して対応するテストが落ちることを確認する。壊すときは `git checkout` を
使わず、scratchpad に控えを取る。**検出できない変異は、検出できないことを記録に
残す。** 特に「現行グループなら `skipped` にする」を外す変異が、**元の 4 本が
戻ることを見るテスト**で落ちること。

## この設計に含まれないもの

| 項目 | どうするか |
| --- | --- |
| **元ファイル（カードから取り込んだもの）を消す** | 入れない。消せるのは結合物だけ |
| **Immich 側の資産を消す** | 入れない。こちらから相手のライブラリを削らない |
| つなぎ目の警告が実カードでは毎回出る | 単独で直せる。閾値を時刻の分解能に合わせる |
| Immich の説明欄に `default` が出る | 単独で直せる。プロファイルが「捨てる説明」を宣言する |
| `origin = unknown` を「先に誰かが上げた」と描いている | 単独で直せる。書き分けるだけ |
| §9.10 の「ゴミ箱にある」「リモートに存在しない」を**送り先の画面**が出していない | この設計では**くわしく画面にだけ**出す。設定 › 送り先の一覧と `requeue` の入口は持ち越しのまま |

**`../design.md` §13 の更新は実装と同じ PR で行う。** 仕様の正本と画面が食い違う
時間を作らない。
